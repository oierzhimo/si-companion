# 2.0.0a7 局域网协同预览

状态：2026-10-26。2.0.0a7 没有改动局域网协议、事件账本或存档格式，配对与交换流程沿用 2.0.0a6。此前已在一台 Windows 电脑中运行两份隔离存档，通过真实 TLS 套接字和 Qt 面板验证；2.0.0a3 冻结 EXE 也完成过配对与交换。2.0.0a5 修正了空白桌面新装也生成零值迁移基线的问题，双独立进程回环用例已独立运行通过；2.0.0a7 冻结包也已在本机完成启动、TLS 配对与事件交换自检。尚未验证第二台物理电脑。

## 使用

便携包完整解压后使用 `Start-Sync-Preview.cmd` 启动，打开“相伴手记 → 局域网配对与同步”。源码可安装 requirements.txt 后以 `main.py --sync-preview` 启动。默认不监听网络，也不自动连接。

1. 在一台电脑上点击“生成 3 分钟配对邀请”，复制邀请。
2. 在同一局域网另一台电脑中粘贴邀请，点击“连接对方设备”。邀请只可使用一次，超时需重新生成。
3. 在连接的一端点击“现在同步”。双方互动和手记会进行双向合并。可勾选每分钟自动连接；退出程序后停止。
4. 邀请生成端需要继续运行。关闭配对窗口后接收仍保持开启，可重新打开并选择“停止接收”。
5. 生成邀请的一端可撤销某台设备的接收授权；原密钥此后不能发起新请求。连接的一端可以删除本机保存的连接。

通常会自动填写本机局域网地址。多网卡或端口冲突时可展开“连接设置”调整。127.0.0.1 只适合同机演练，不能交给另一台电脑。程序不自动添加 Windows 防火墙规则。

## 存档起点

启用局域网预览时，设置偏好仍留在本机 settings.json，只有互动计数与手记进入旁边的 settings.sync-v1.json 事件账本。

- **全新桌面安装**（pats、snacks、focus_sessions、affinity 全为 0，且 history 为空）会像安卓/鸿蒙新装一样，直接持久化一个带本机设备 ID 的空账本，不再写入零值 legacy_snapshot。这样它可以接收一台已有 PC 的非零迁移基线，不会在首次交换时因“两份迁移基线”被拒绝。设备 ID 在生成后立即落盘，掉电或重启不会更换。
- **非空旧存档**（计数非零，或计数为零但 history 非空）仍按原规则生成一条由内容哈希决定事件 ID 的 legacy_snapshot，并在首次启用时备份为 settings.pre-sync.json。从同一份旧内容迁移的多台设备共享同一个迁移 ID；两份内容不同的非空旧存档仍会被拒绝，必须人工决定如何迁移，程序绝不自动相加或合并。
- 已有非空 history、即使所有计数为零，也保留迁移基线，不会当作空白安装丢弃。
- 首次启用时，如果旧手记虽非空但含有无法原样保留的条目（例如不是带 `at`、`text` 字符串的记录），程序会拒绝建账本并保持旧设置原样；请先备份并人工核对，不会静默丢弃或改写手记。合法旧手记照常迁移。
- 设置偏好（窗口、音量、动画等）只保存在本机，不随同步事件包发送。
- 每台设备必须保有自己的 settings.sync-v1.json 设备身份，不要复制另一台的账本。

### 从 a3/a4 升级的限制

a3/a4 可能已经为空白存档生成了零值 legacy_snapshot。本次没有自动改写或删除这种旧账本：它可能已经包含手记事件，自动清理会丢数据；两份旧账本也可能已经分叉。因此：

- 旧零值账本与一台有非零基线的 PC 配对时，仍会按“不相容的迁移基线”拒绝交换。
- 只有在确认该旧账本除这一条零值 legacy_snapshot 外没有任何其他事件、本机 history 为空、且已自行备份 settings.sync-v1.json 时，才可删除该账本并重新以协同预览启动，让程序生成空账本。这会更换本机设备 ID，已配对的对端需要重新配对。无法确认时不要删除，保留现场后人工处理。
- 两台都已有非空旧存档的设备仍然不能直接配对合并；不要为了让它们连上而删掉任一方的累计。

## 实现

- HTTPS 使用本机独立证书，连接端在发送邀请密钥或互动数据前核对邀请中的证书 SHA-256 指纹。证书生成依据 [cryptography 的 X.509 文档](https://cryptography.io/en/latest/x509/tutorial/)。
- 一次性随机邀请有效期 180 秒；每个已配对设备有独立密钥，可撤销。接收端保存的授权、本机证书与连接记录都在存档旁的 settings.lan 目录。
- 仅接受 IPv4 私有局域网与回环地址。传输不经第三方服务器。请仅把邀请交给管理员自己的设备，邀请本身含配对凭据。
- 网络请求在工作线程执行，所有真实 Store 合并和面板刷新通过 Qt 信号回到界面线程。重复请求按事件 ID 去重，中断后可重试。
- 首版交换完整事件包，仍受现有 5 MB、10000 事件上限约束；按缺失 ID 增量传输尚待实现。

## 已验证及未验证

6 项真实 TLS 单元检查覆盖双向合并、重复重试、单次与过期邀请、证书不匹配、撤销授权、旧迁移基数冲突，以及外部地址拒绝。Qt 集成检查实际点击配对和同步按钮，确认主线程写入、面板计数更新、自动定时连接、撤销后拒绝新增事件。报告在 qa/lan-sync-integration.json，截图在 qa/lan-sync-dialog.png。

新增的 tests/test_lan_two_process.py 使用两个独立操作系统进程（各自临时目录与设备身份），在 127.0.0.1 上沿用生产 Store、LanServer、PeerRegistry、pair 与 exchange，覆盖：空白新 PC 与带旧记录的 PC 配对、TLS 证书指纹核对、双方各自新增事件后的双向合并、重复交换幂等，以及两个进程重启后设备 ID、证书指纹和已有授权保持并可继续同步。它只监听回环地址，不读取用户存档，测试结束会终止两个子进程；它是同机回环，不是第二台物理 PC。独立复测通过，完整 73 项单元测试和源码面板集成检查也通过。

尚未验证第二台物理 PC、Windows 防火墙实际放行、换网与换 IP 的连接修复、安卓或鸿蒙客户端。不能据此认定完整多端协同已经完成。
