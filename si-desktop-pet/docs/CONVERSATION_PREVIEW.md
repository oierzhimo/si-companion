# 自由对话与国内开源模型预览

2026-10-27：已完成本机 GenAI 反代部署与本人登录、132 项源码测试、六轮真实 DeepSeek 合成对话，以及源码 Windows Qt 界面的真实获取模型、发送和保存检查。2.0.0a8 包含此功能，归档和异地冻结核验以独立发布报告为准。长期角色质量仍未定稿；运行时动画沿用旧素材，移动端尚无自由对话入口。

## 入口与两种服务

从首页“自由聊聊 · 本机或学校反代”进入。窗口不会在打开时自动获取模型、自动发送对话或发送空测试消息；只有用户点击“发送”才发起聊天，只有点击“获取模型”才查询模型列表。

- **普通本机模型**：填入本机运行中的 OpenAI-compatible `/v1` 接口和模型名。默认示例为 `http://127.0.0.1:1234/v1`，反代访问口令留空。
- **上科大 GenAI 反代**：默认 `http://127.0.0.1:8000/v1` 与 `DeepSeek-V4.1-Flash`，可主动选 `GLM-5.3-Flash`。GenAI 预设只提供这两个已核对官方 MIT 模型卡的国内型号，其他型号和 GPT 都会在保存或联网前拒绝，不自动换用 GPT。反代访问口令字段为密码显示，公开缺省本机口令 `sk-shanghaitech-genai` **不是学校登录 Token**。

反代访问口令只保留在进程内存中，不写入 `conversation.json`、不参与设备同步、不进入请求正文或日志，也不会读取其他软件保存的口令。关闭应用后不会保留；若使用自定义口令，下次需要重新填写，实际口令以本机部署为准。

## 本机部署边界

本机上游 `cgz12345/shanghaitech-genai-proxy` 固定公开 commit 为 `4b70794b80704dc9baa90314149e8e04d0705260`，已使用独立环境和 Waitress CLI 监听 `127.0.0.1:8000`。登录由用户本人完成，健康检查及模型列表有效。桌宠不读取学校 `token.txt`、凭据或 Claude 设置，也不启动或修改上游服务；该部署入口不自动打开浏览器续期。

客户端只允许 `http://` 回环地址，不跟随重定向、不使用系统代理、不自动重试。聊天请求最多等待 90 秒；模型列表请求最多等待 20 秒；响应大小上限同为 2 MiB。认证只通过 `Authorization: Bearer <反代访问口令>` 请求头发送。

- 聊天：`POST /v1/chat/completions`
- 模型列表：`GET /v1/models`（读取 `data[].id`）
- 反代返回 401/403：提示“本机反代访问口令有误”。
- 反代返回 503：提示反代或学校登录不可用，请先完成学校登录并确认服务正在运行。
- 反代返回 429：提示服务忙，稍后重试。
- 其他错误只显示状态或友好说明，不显示上游响应正文、口令或密钥。

## 模型名与选择

不猜测模型名，也不把协议测试桩当成真实模型。填写反代地址和口令后，明确点击“获取模型”，客户端才会在后台线程查询；结果去重、限制为最多 200 个短标识，并通过模型输入框的补全列表供选择。查询期间 Qt 主线程保持响应；重复点击不会并发查询。关闭窗口或切换服务后，迟到的模型列表不会更新窗口，也不会覆盖用户后来选择或输入的模型；查询失败时保留已有模型、草稿和口令，仍可用已有模型发送。

模型列表格式异常、为空或过大时显示友好错误。GenAI 预设会按上述两个国内型号精确筛选，匹配时保留服务返回的规范拼写；没有匹配则提示检查服务，不能回退 GPT。普通本机预设兼容自部署的 OpenAI-compatible 模型名称，明显带 GPT/OpenAI/ChatGPT 命名的型号仍会在发送前拒绝；这项检查只看名称，普通本机并不核验其他任意名称是否确属国产开源模型。

## 记录与隐私

最近 12 轮历史、管理员偏好、接口地址、模型名和服务类型（`local` / `genai`）写入当前存档目录的 `conversation.json`，不写入同步账本。旧存档无服务类型时按普通本机处理。打开窗口不改写旧文件；旧 GenAI 的 GPT/未核验型号在窗口内改为 DeepSeek，普通本机的 GPT 型号在窗口内清空，历史和偏好保留。发送前再次按当前预设规则校验，成功提交新配置时才保存。反代访问口令永远不会保存。

普通本机模型只连接本机服务。选择上科大 GenAI 反代时，本次文字、偏好和最近 12 轮会经本机反代送到学校模型；**这不是纯离线对话**。桌面客户端只在本机保存对话记录，反代及学校服务如何处理或记录内容取决于该服务。回复是模型生成内容，不标为官方台词。较短回复可走既有气泡/可选语音，超过 160 字仅显示在对话框，避免遮挡桌面。

## 生命周期与错误恢复

对话发送沿用已验证的 generation / active_generation 语义：工作线程只发 Qt 信号，不直接操作控件；关闭窗口、清除历史或切换请求后，迟到回复不写记录、不播语音、不解除新请求的等待态。保存失败会回滚内存历史并保留输入。模型查询同样使用独立 generation，关闭、切换预设或编辑连接后旧结果被忽略。

## 验证范围

新增的 `tests/test_conversation_genai.py` 使用仅监听 `127.0.0.1` 的协议桩，覆盖：

- Bearer 头准确且不出现在正文/存档；旧三参数调用无认证头。
- 401/403/503/429/500 友好错误且不泄漏上游正文或口令。
- 重定向不跟随、口令不转发；CR/LF、过长、非字符串口令被拒绝。
- 模型列表认证、去重、200 项/200 字符上限、畸形/超大响应和状态错误。
- Qt 预设默认值、旧存档保留、显式异步获取模型、主线程不卡顿、重复点击不并发。
- 关闭/重开/切换服务后迟到模型列表不覆盖新选择；获取模型失败后仍可发送已有模型。

协议桩不代表学校服务。主协作者已独立运行全套 132 项测试并通过，期间两个生产模块和对应测试源码哈希不变；另实际运行 `tools/check_genai_live_v3.py --run-live` 的六轮 DeepSeek 测试及源码 Qt 界面真实发送，保存与重载一致。记录位于 `qa/domestic-client-full-tests-v1.json`、`qa/genai-live-v3/report.json` 和 `qa/genai-ui-live-v2/report.json`。后两者的角色质量标记仍为 false，不能用连通成功替代人设验收。源码界面真实发送也不等于冻结 EXE 界面真实发送。开发时可复测：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -p "test_conversation*.py" -v
```
