# 2.0 多端协同协议草案

状态：协议草案及 Windows 2.0.0a1 便携版手动同步预览。`src/si_pet/sync_v1.py` 已实现事件校验、旧存档迁移基数、幂等合并、摘要校验和派生计数。通过便携包的 `Start-Sync-Preview.cmd` 或源码 `--sync-preview` 启动时，摸头、点心、专注完成和手记写入独立的 `settings.sync-v1.json`；首次启用前复制 `settings.json` 到 `settings.pre-sync.json`。面板“相伴手记”页提供事件包导入/导出，导入后更新亲密度、次数和手记，保留本机缩放等设置。`tools/sync_v1_cli.py` 仍仅供隔离测试目录演练账本，不改写桌宠旧存档。尚无自动配对、移动端安装包或跨设备实测；不能据此宣称完整多端协同。

## 平台边界

- Windows 多 PC 继续使用本项目的本地存档。每台设备有独立的窗口坐标、缩放、置顶、穿透、启动项与语音播放设置。
- Android 客户端需单独实现应用内伙伴视图；仅在用户授权且系统允许时提供悬浮窗。Android 15 对从后台启动前台服务的悬浮窗豁免要求悬浮窗**已经可见**，不能把“有悬浮窗权限”当作可任意常驻的保证。参考 [Android 官方说明](https://developer.android.com/about/versions/15/behavior-changes-15)。
- HarmonyOS 5 平板需要独立的 ArkTS 应用；华为明确说明 HarmonyOS 5.0 及以上不兼容 Android 格式应用，不能把 Android APK 当作鸿蒙交付物。参考 [华为开发者说明](https://developer.huawei.com/consumer/cn/games/devstart/) 和 [ArkTS 概述](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/arkts-overview)。系统是否允许目标设备上的桌面级悬浮表现须用该平板真机验证；不可实现时先提供应用内角色与通知。

## 同步内容

| 数据 | 合并方式 | 范围 |
| --- | --- | --- |
| 摸头、点心、专注完成 | 每次产生唯一事件；按事件 ID 幂等并集，再计算计数 | 同步 |
| 相伴手记 | 每条记录有稳定事件 ID；离线合并时保留全部有效记录 | 同步 |
| 关系与亲密度 | 由已合并事件确定性计算；旧存档须有一次性迁移基数 | 同步 |
| 用户主动设置的共享偏好 | Lamport 版本 + 设备 ID 决定冲突胜者，保留冲突审计 | 可选同步 |
| 宠物坐标、窗口平台、悬浮权限、音量、置顶、自启、安静模式 | 各设备独立 | 不同步 |

## 事件格式 v1

```json
{
  "protocol": 1,
  "event_id": "device-uuid:42",
  "device_id": "device-uuid",
  "sequence": 42,
  "lamport": 87,
  "kind": "focus_completed",
  "payload": {"minutes": 25},
  "occurred_at": "2026-10-25T09:00:00+08:00"
}
```

- `event_id` 是幂等键。相同 ID 且内容不同视为冲突并拒绝自动覆盖。
- `sequence` 在设备内单调递增；时钟只用于显示，不能决定计数或覆盖结果。Lamport 值在接收事件后推进，用于设置项冲突决议。
- 传输批次有内容摘要、来源设备 ID 和协议版本；未知版本只存放于待处理区，不写回旧版存档。
- 旧版 `settings.json` 迁移时先保留原文件备份，再把累计值转为稳定的迁移基数。复制自同一旧存档的两台 PC 必须得到同一个迁移基数 ID，防止合并时重复计数。
- 迁移事件根据已有计数与手记内容生成稳定 ID。若两台电脑在首次迁移前已各自修改了复制来的旧存档，无法可靠识别共同祖先；当前账本会拒绝自动合并，后续迁移界面须提示人工处理，不能把两个累计快照相加。
- 手动同步预览的可选记录模式会继续维护旧版 `settings.json` 中的累计值，用独立账本作为新增互动的权威记录。若旧版程序随后单独增加计数，下一次启用同步预览会检测到旧累计值超前并停止；若账本事件已落盘而旧计数尚未写入，则按账本恢复计数。该模式未加入 1.2.2 已发布的便携包。

## 配对与传输

源码 2.0.0a3 已加入显式开启的 TLS 局域网交换、180 秒一次性邀请、证书指纹核对、每设备密钥和撤销，以及每分钟自动重连。仅在本机两份隔离存档中通过真实网络与 Qt 检查；首版仍发送完整事件包，增量协商、第二台真机和移动端未完成。详情见 `LAN_SYNC_PREVIEW.md`。当前 2.0.0a2 便携包不含这些新增入口。

1. 管理员在一台已解锁设备上主动生成一次性配对码或二维码；另一台设备确认名称与短验证码。配对后保存设备身份，可主动撤销。
2. 先实现人工导出/导入事件包来验证合并语义，再接入经认证的局域网传输。跨网络连接与中继选项必须单独设计，不把私人数据默认上传第三方。
3. 每次重连先交换设备摘要与缺失事件 ID，只补缺失事件。写入完成后回传确认；重复投递、乱序、时钟偏差、离线并发与中断重试均须保持结果一致。

## 验收门槛

- 两台 PC、Android 手机、HarmonyOS 5 平板分别完成安装、配对、主动互动、离线写入、重连合并与撤销配对的实机检查。
- 用同一组离线事件做顺序、逆序、重复导入，四端计算的亲密度、专注次数和手记 ID 集合必须一致。
- 确认移动端权限拒绝、后台限制、重启与退出路径；不能提供悬浮窗时应用内伙伴仍可用。
- 位置、权限和窗口几何不得从一台设备覆盖另一台设备的本地状态。
