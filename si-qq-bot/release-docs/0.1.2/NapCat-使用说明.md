# NapCat 使用说明

适用于“小祀 QQ 私聊连接器 0.1.2”Windows x64 便携版。连接器本身不包含 QQ、NapCat 或模型代理，也不会代替你登录 QQ、扫码或绑定账号。

## 1. 准备条件

- 从 0.1.1 升级时，先断开并完全退出旧版及其控制台，确认旧版后台任务已结束，再启动 0.1.2。旧版没有本版的目录锁，不可同时运行。
- Windows x64。
- 一个专门给小祀使用的普通 QQ 账号，以及可扫码登录该账号的手机 QQ。
- 本机已安装 QQ 和 NapCat，并已在本机运行已部署的模型代理。
- 电脑、QQ/NapCat 和模型代理需保持运行。模型代理不是本发布包的一部分，当前是否可用需以实际检查为准。
- 如需补装，NapCat 相关组件只从官方 GitHub Release 原站获取，Node.js 只从 `nodejs.org` 官网获取；不建议使用镜像、代理下载站或第三方重打包文件。

不要使用自己的日常主账号做试验。NapCat 是第三方 QQ 接入软件，普通 QQ 账号经其接入时，登录数据与其他 QQ 数据是否隔离取决于实际安装和配置，本连接器不作保证。

## 2. 创建并登录 NapCat 实例

1. 打开 NapCat Desktop，在组件页确认本机 QQ 与 NapCat 组件可用。
2. 在“机器人”页新建一个本机 NapCat Bot 实例，选择专用 QQ 账号。首次排查时建议先不要开启掉线自动重启或定时重启，以免掩盖登录问题。
3. 启动该实例，在 NapCat 自己的登录界面用手机 QQ 扫码。扫码和账号确认必须由你本人完成；连接器不会代登录，也不会读取 QQ 密码。
4. 确认 NapCat 当前登录的确实是专用账号，并保持该实例在线。

若 NapCat 显示的登录账号不是专用账号，请先退出并重新确认，不要继续配置绑定。

## 3. 配置本机正向 WebSocket

在该实例的“连接”页新增“WS 正向服务器”，按下表配置并保存：

| 项目 | 配置 |
| --- | --- |
| 监听 IP | `127.0.0.1` |
| 端口 | `3001` |
| 路径 | `/` |
| 客户端连接地址 | `ws://127.0.0.1:3001/` |
| 连接角色 | `Universal（API + 事件）` |
| 消息上报格式 | `Array` |
| 鉴权 | 启用，使用本机生成的 OneBot Token |

保存连接后，再保存该 Bot 实例的配置。只允许本机回环地址，不要把监听地址改为 `0.0.0.0`、局域网地址或公网地址，也不要在路由器上转发该端口。不要把 WebSocket 或 NapCat WebUI 暴露给他人。

连接器只使用本机地址 `ws://127.0.0.1:3001/`，不会连接其他主机。

## 4. OneBot Token

- OneBot Token 由 NapCat 在本机生成，用户在本机自行输入。它不同于 QQ 密码，也不同于 NapCat WebUI 密码。
- 连接器每次启动都需要重新输入 Token，只在本次运行的内存中使用，不写入发布包，也不随日志或文档分发。
- 本发布包不预置任何 Token。不要把自己的 Token 写入截图、聊天记录、工单或公开配置；如怀疑泄露，请在 NapCat 中更新鉴权配置，并同步修改连接器中的输入。
- Token 输入错误时，连接会失败；请检查是否复制了完整 Token，以及是否有额外空格。

## 5. 启动连接器、核对账号并绑定

1. 确认 NapCat 实例已登录专用账号，正向 WebSocket 已启动，且模型代理正在运行。
2. 解压发布包，运行 `SiQQ-0.1.2-Windows-x64.exe`。程序会打开主窗口和一个控制台窗口。
3. 保持控制台窗口打开。控制台被关闭时程序会结束；它不是可以随意关闭的日志窗口。
4. 在“本机连接地址”中确认是 `ws://127.0.0.1:3001/`，输入 OneBot Token，点击“连接”。
5. 连接成功后，先核对窗口显示的 QQ 账号号码是否与专用账号完全一致。若尚未识别或号码不一致，立即点击“断开”，不要生成绑定码。
6. 号码一致时，点击“生成绑定码”。绑定码 5 分钟内有效；用管理员自己的 QQ 私聊该专用账号，发送 `绑定 <绑定码>`（把 `<绑定码>` 换成窗口显示的内容）。
7. 绑定成功后，连接器只回应这个管理员账号的好友私聊，不会向群聊或未绑定好友主动发消息。绑定操作由你本人完成，连接器不会自动绑定，也不会自行更换管理员。

“本机绑定”只改变本机连接器的授权状态，不会修改 QQ 好友关系，也不代表腾讯侧或其他 QQ 客户端认可该绑定。

## 6. 日常使用

- 保持电脑、QQ/NapCat、本机正向 WebSocket 和模型代理运行；任一环节离线都可能导致无法回复。
- 消息会经过腾讯 QQ 平台和本机模型代理处理，并非纯离线。QQ 对话保存在本机 `%LOCALAPPDATA%\SiCompanion\QQPrivateChat`，与桌宠原有对话分开。
- 结束使用时，先点击“断开”，再关闭主窗口；如程序无响应，再关闭控制台窗口结束进程。不要在模型仍在处理时强制结束多个实例。
- 如果更换了专用 QQ 账号或 Token，先断开旧连接，再按上述步骤重新登录、核对和绑定。

## 7. 运行问题和“结果不明”

遇到运行问题时，先断开并关闭程序，再检查本机窗口提示、NapCat 的登录和连接状态、模型代理是否在运行，以及 Token 和地址是否正确。不要通过关闭鉴权、开放端口或使用镜像来绕过问题。

如果程序提示上一条 QQ 回复的投递结果不明：

1. 不要自动重发，也不要反复点击发送或恢复。
2. 先在 QQ 客户端和本机窗口中核对实际结果。
3. 确认后，由你手动点击“恢复未确认回复”并阅读确认框。该操作只清除本机未确认状态，不会重发那条回复，也不能判断腾讯侧是否已经送达。
4. 恢复完成后再继续聊天；若恢复未完成，保留未确认状态并检查本机存储，不要另开实例覆盖。

## 8. 验证边界

本次 0.1.2 准备的验证范围如下：

- 本机 QQ 和 NapCat 组件已安装，专用账号已由用户登录。
- 87 项模拟与离屏测试通过。这些测试不登录真实 QQ、不发送真实消息，也不调用真实模型。
- 真实私聊收发及模型回复尚未验证，不能据此声称端到端成功。
- 模型代理当前是否可用尚待确认；不要根据旧状态假定它仍在线。
- 真实账号的消息送达、账号隔离和长期稳定性仍需你本人用专用账号完成验收。

本说明和发布包不写入用户 QQ 号码、用户 OneBot Token、学校登录凭据或聊天记录。程序使用内置的本机模型代理默认鉴权值。连接器不读取 QQ 密码，不保存 QQ 账号令牌，也不会自动扫码或自动发起聊天。
